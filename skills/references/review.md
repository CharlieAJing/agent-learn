# 审稿指南

## 提纲自查

- **范围**。逐项核对学习目标，补上遗漏的问题，移除超出目标的内容。
- **结构**。将问题放入合适的小节，先讲后文依赖的知识。按 [Ask 要求](material-generation.md#ask-要求)合并重复的自测题，明确每题要考查什么。
- **依据**。核对已读资料能否支撑各节讲解和问题作答。发现缺口时，明确哪个问题缺少什么依据，再定向补查。

## 完整审稿

串行启动两个独立上下文的 subagent（`fork_turns: "none"`），提供用户需求、审定提纲、当前成稿及审稿规范。涉及检索、制图或渲染的检查，提供对应底稿、附件或验证结果。先做内容审稿，主 Agent 核实意见、修订并复查后，再启动阅读体验审稿，审查修订后的成稿。两个 subagent 只提交意见，由主 Agent 按[修订与复查](#修订与复查)统一改稿。

### 内容审稿

1. **逐项核对原要求**。按用户需求和审定提纲，逐行核对[资料生成指南](material-generation.md)全文（含各节「提示」）及[表达要求](../SKILL.md#表达要求)。同一行有多项要求时分别判断，按原文区分必做、按需和示例。在底稿中为每项标明判定：「已满足」给出成稿位置或执行依据，「待补」指出缺失或尚未核实之处，「不适用」说明理由。
2. **通读验证内容**。对照学习目标检查遗漏和偏题，按[思考原则](thinking-principles.md)回查关键结论的原始出处，核实引用位置、推理和适用条件。连读正文、图表与问答，核对术语和结论是否一致，正文是否讲清每道题所需的依据。
3. **复核改稿**。将待补项和通读发现的问题列入[审稿意见](#审稿意见)。修订后按原要求复核改动处及受影响的内容。

### 阅读体验审稿

你是一位注意力稀缺、善于归纳重点的快速学习者，欣赏简洁直观的表达。

先读[章节框架](material-generation.md#章节框架)，明确各节要回答的问题。提出改法时，核对改后读者仍能从正文找到原意和必要依据。

仅依据本句及前文，检查关键表述的对象、含义和必要前提是否已经交代；需要读者自行猜补的，先改清楚再评分。

依据[审美直觉](../SKILL.md#审美直觉)四项分别评分（10 分制），结合具体段落说明主要扣分原因，优先提出最值得改进的问题。

## 审稿意见

每条意见写明位置、问题和改法。未能核验时写明原因；未发现问题时直接说明。默认审查文本与结构。

## 修订与复查

**动笔前**，重读本次涉及的用户要求和目标内容对应的规范，明确要解决的问题，以及改后读者仍需理解或完成什么。

**改稿后**，对照成稿核验这两个目标。按改动的实际影响选择复查方式：

- 仅作文字或链接勘误，直接核实更正结果。
- 可能影响含义、依据或完整性，按[内容审稿](#内容审稿)核对改动处及依赖它的部分，确认必要结论仍有充分解释和依据。
- 可能影响表达、结构或衔接，按[阅读体验审稿](#阅读体验审稿)连读改动处与前后文。两类影响兼有时，先查内容，再查阅读体验。

影响范围不清时，执行[完整审稿](#完整审稿)。

同一任务中，每篇稿件最多自动审 **5 轮**（含首轮，内容与体验合计一轮），通过即停，到上限仍有问题就列出并停止。

## 问题采样与优化提醒

- **采样**。首次核实可复现问题时登记。内容完成后，在[采样记录](../review-samples.md)中为每个适用且已检查的问题记一次命中或未命中，修稿后仍算命中。
- **判定**。交付前运行 `python3 skills/scripts/check_review_thresholds.py`。本轮累计命中 ≥ 3 次，或最近满 5 个样本且命中 ≥ 2 次，即触发。
- **提醒**。附触发依据和实例，指出规则缺口或执行遗漏。有改文时经用户确认后执行。每轮提醒一次，提醒后标记“已提醒”，继续采样。
- **清零**。落实对应优化或用户要求时，仅该问题进入下一轮，恢复“观察中”，记录日期和原因，保留历史样本。
