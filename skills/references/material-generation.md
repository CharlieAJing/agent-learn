# 资料生成

## 流程

完整生成或覆盖重写时，主 Agent 按以下顺序推进，一次交付成稿。

1. **拟提纲**。围绕学习目标，按[章节模板](#章节框架)列出章节和问题，「提示」原样保留。
2. **提纲打磨**。围绕提纲中的问题[搜集资料](research.md)，将结论、适用条件、出处和待核实点记入工作区的临时底稿。按[提纲自查标准](review.md#提纲自查)调整章节和问题。发现证据缺口就补查，确认提纲和资料足以支撑写作后再动笔。
3. **写正文**。按审定的提纲写完整篇正文，讲清各节问题。写作中如新增问题或改变结论，将涉及的部分带回「提纲打磨」环节。
4. **写答案**。正文完成后，按[作答要求](#作答要求)逐题回答。若正文不足以支撑某个回答要点，把缺失的解释写成具体问题，核实资料后，带着这个问题在原定学习目标内重写相关小节。确认重写后的正文足以支撑该题及受影响的其他题目，再完成答案。
5. **完整审稿**。按[完整审稿流程](review.md#完整审稿)串行执行内容审稿和阅读体验审稿。复查通过后，从交付稿中删除模板「提示」，仅保留正文和学习问答。最终交付后删除本任务的底稿。

## 内容要求

- 正文按知识点整合多个来源，在对应章节集中讲解。
- 正文与答案均须独立可读，理解无需跳转链接。
- 出处就近标注，尽量定位到原文章节。
- 采用外部图片时，保存到本地并嵌入正文。

## 问答

### Ask 要求

- 围绕主题知识设计 Ask（✅ LLM Agent 是什么？；❌ 本文采用的 Agent 定义是什么？），**每题一个回答目标**，合并重复、琐碎问题。
- 按知识依赖从零基础到专家逐级展开（深度），引导用户**理解概念、解释原理、串联知识、提炼方法、迁移应用**。
- 对支撑后续理解、决定方案取舍或容易混淆误用的知识点重点拷问，可采用苏格拉底式诘问。
- 梳理资料时可动态追加 Ask；初始问题 `A01、A02…`，追加问题 `B01、B02…`。
- 新信息或前提变化时，同步修订相关问题与答案。

### 作答要求

- 每个 Ask 下紧接对应答案，采用 Obsidian 默认折叠块 `> [!faq]- 答案`；问题编号仅在 Ask 中标注，答案归属由相邻位置表达。格式见章节模板。
- 答案的依据可通过正文引用追溯。直接引文就近标注原出处。
- 正文应讲清答题所需的依据和条件，缺什么就补什么。

## 章节框架

按主题选用备选问题。

- [思考原则](thinking-principles.md)贯穿全文，各节按需标注推荐原则，可自由扩展其他原则或更多思维方式。
- 需要深入时，可按类型学习不同做法，也可按组成要素深入其作用与机制。
- 按主题调整章节框架；修改已交付资料的目录时标注**增删及去向**，经用户确认后清理标记。
- 框架仅允许按主题增删、合并、拆分或重命名章节及小节，其余结构保持不变。
- 章末或可独立学习的小节末按需设 `### Ask`，跨章综合题放在文末。
