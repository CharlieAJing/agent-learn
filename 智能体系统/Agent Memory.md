# Agent Memory

## 概念

### 定义

**智能体记忆（Agent Memory）**是智能体保存信息、在后续决策中重新取用并维护其有效性的机制。本文以**大语言模型（Large Language Model，LLM）**智能体的外部显式记忆为主：信息存于模型参数之外，可由程序读取、修改和删除。它既可以服务同一任务的连续执行，也可以跨会话复用。

不同来源的范围并不完全一致。LangChain 把会话内状态也纳入记忆；Anthropic 的一篇工程文章则将 Agent Memory 限定为跨会话保留的经验知识。阅读资料时，应先核对讨论的是哪一种范围。[LangChain，Memory overview](https://docs.langchain.com/oss/python/concepts/memory)；[Anthropic，Memory notes](https://www.anthropic.com/research/components-of-agent-memory)

**上下文**是某次模型调用实际收到的信息；**工作记忆**是当前决策可操作的状态，可能比本次输入更大。CoALA（Cognitive Architectures for Language Agents，语言智能体认知架构）将工作记忆视为跨模型调用保留的数据结构，并从其中选取内容组成输入。[CoALA，§4.1](https://arxiv.org/html/2309.02427v3#S4.SS1)

<span style="color: var(--color-red)">记忆的价值取决于未来需要的信息能否被正确保存、及时取用并正确使用，而不是存了多少内容。</span>

### 核心价值

记忆缓解跨调用、跨会话的信息断裂，让后续任务能够继承已确认的信息和经验。一次普通模型推理不会自动把本次交互写入模型参数；系统必须显式保存与重新供给信息，才能建立这种连续性。

完整历史也不能无条件代替记忆管理。**上下文窗口**是一次调用可容纳的输入与输出范围；输入变长会增加资源消耗，且可容纳不等于可可靠利用。压缩和选择能减少输入，但也可能丢失条件与证据。[Anthropic，Why context engineering is important 与 Context engineering for long-horizon tasks](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

因此，记忆解决的是“哪些过去的信息值得影响现在”。如果过去的信息无用、已失效或来源不可信，继续保留和使用反而可能降低效果。这是本文据上述机制作出的工程判断。

### 相似概念

下表按职责比较，不是互斥技术分类。

| 名称 | 说明 | 优点 | 局限与适用条件 |
| --- | --- | --- | --- |
| 上下文 | 本次模型调用收到的信息 | 直接参与当前生成 | 容量和成本受限；适合当前必须使用的内容 |
| Agent Memory | 保存、取用和维护后续可复用的信息 | 支持任务连续性与经验积累 | 会漏记、误记和过期；适合存在历史依赖的任务 |
| 检索增强生成 | Retrieval-Augmented Generation（RAG），检索外部信息后辅助生成 | 能按需供给资料 | 仅有检索不包含完整写入与更新机制；适合依赖外部资料的回答 |
| 检查点 | 保存某个执行时刻的系统状态 | 支持恢复执行 | 状态快照不自动成为跨任务知识；适合中断恢复 |
| 参数更新 | 通过训练改变模型内部参数 | 能改变模型的一般行为 | 不便逐条追溯、替换和删除知识；适合需要训练的能力改变 |

记忆可以使用 [[RAG|RAG]] 检索历史，也可以直接读取少量结构化记录。外部知识库也可以供给事实与知识，但内容不一定来自智能体的经历；因此，不能只凭“能够检索历史”判断系统已经具备完整记忆能力。

> [!faq]- A001：Agent Memory 与上下文有什么区别？
> 记忆负责让信息在以后仍可取用，上下文是某次调用已经收到的信息。存入外部记忆不意味着模型当前看得见；需要读取并纳入输入，才能影响该次生成。工作记忆还可以包含未放入本次输入的任务状态。

> [!faq]- A002：为什么 RAG 不能直接等同于 Agent Memory？
> RAG 说明如何检索信息辅助生成，Agent Memory 还涉及保存什么、如何更新、何时失效以及如何删除。RAG 可以实现记忆的读取部分，也可以只检索与智能体经历无关的外部资料。

## 工作原理

### 基本过程

以下是本文整理的六步生命周期，描述一条信息从产生到后续复用的过程。实际系统会重复执行这些步骤，并不要求所有步骤在同一会话内完成。

```text
开始 → ①采集 → ②筛选与整理 → ③保存 → ④按需读取
     → ⑤组装与使用 → ⑥核验与维护 → 本次生命周期结束
```

1. **采集**：记录交互、工具结果和任务反馈，保留信息来自哪里、何时产生，以及所属用户或任务。采集到的内容只是候选材料，不保证真实。
2. **筛选与整理**：判断未来是否可能需要，分开事实、推断和未完成事项；将冗长内容压缩成仍保有条件的记录。被判定无须保存的材料不进入长期存储。
3. **保存**：写入可持久保留的文件或数据库，记录版本与访问范围。需要搜索时建立**索引**，即帮助定位记录的辅助结构；保存成功与索引可查应分别检查。
4. **按需读取**：根据当前目标确定查询，先限制可访问的用户、任务及时间范围，再从允许范围内寻找相关记录。检索失败不代表历史中一定没有信息。
5. **组装与使用**：检查记录是否仍有效，保留来源及必要前提，将选定信息放入上下文。模型据此回答或行动；记忆内容本身不授予新的执行权限。
6. **核验与维护**：对照实际结果发现错误、冲突和过时内容，更新或撤销记录，并同步处理索引与派生摘要。新的反馈可成为下一次生命周期的输入。

这套流程把记忆当成信息维护系统。CoALA 对检索与学习动作的区分提供了架构依据，但上述六步及检查项是本文的工程整理。[CoALA，§4.3、§4.5](https://arxiv.org/html/2309.02427v3#S4.SS3)

### 关键组成

| 名称 | 职责 | 输入与输出 | 检查方法 |
| --- | --- | --- | --- |
| 原始记录 | 保留可回查的依据 | 交互与结果 → 来源记录 | 能否定位原话、时间与结果 |
| 写入管理 | 选择和整理值得保留的信息 | 候选材料 → 记忆条目 | 是否漏掉条件、把推测当事实 |
| 存储与索引 | 持久保存并支持定位 | 条目 → 可读取记录 | 写后回读、索引更新是否成功 |
| 检索与组装 | 为当前任务供给有效信息 | 任务需求 → 当前输入 | 是否取对对象、版本及完整条件 |
| 维护与访问控制 | 管理更新、失效和可见范围 | 反馈与规则 → 有效记录集合 | 过期内容是否停用，越界读取是否被拒绝 |

本文建议一条可审计的记忆至少保留：内容、所属对象、来源、记录时间、适用时间或条件、确认状态和版本。字段多少取决于任务，但必须能回答“凭什么相信、现在是否适用、谁可以使用”。

> [!faq]- A003：为什么保存成功后仍可能表现得像没有记忆？
> 信息可能未进入可查索引、查询没有命中、被访问范围或组装规则排除，也可能已经进入输入却未被模型正确使用。排查应沿保存、读取、组装、使用逐步核对实际产物，不能只检查数据库里有没有记录。

## 能力模型

### 衡量目标

本文定义**记忆链路成功率 Y**：在固定的历史依赖测试任务中，所需历史证据被有效保存、充分送入上下文，并据此完成正确回答或行动的任务比例。测试任务必须事先标注所需证据与成功标准；全部任务数记为 N。

这不是所有任务的整体成功率。无须历史即可完成、靠实时查询绕过记忆、或碰巧答对的任务，不计为这条链路成功。多次检索时，按任务最终供给的证据整体判断，不把每次查询分别当一个样本。

### 逐步分解

令 S 为“所需证据完整且有效地保存在允许访问的记忆中”，R 为“S 成立且所需证据充分进入上下文”，U 为“S、R 成立且最终正确使用证据完成任务”。U ⊆ R ⊆ S。P 表示在固定测试集上的比例，竖线表示“限定在前述条件成立的任务中”。

```text
Y = 记忆链路成功任务数 / N = P(U)
Y = P(S) × P(U | S)
Y = P(S) × P(R | S) × P(U | R)
Y↑ = 有效保存率↑ × 保存后充分供给率↑ × 充分供给后正确完成率↑
```

这是嵌套事件的条件概率分解，不是假定三个因素相互独立。最后一行的方向只在其他因素保持不变时成立；扩大保存范围可能增加干扰，从而降低后续因子。若某阶段没有任务通过，其下游条件比例记为“无样本”，不能随意填成零。

### 优化启示

- **有效保存率**对应①—③及⑥：检查遗漏、摘要失真和过期记录，优先修复未来无法重建的信息损失。
- **保存后充分供给率**对应④—⑤：检查查询、范围过滤、排序与输入裁剪。不能靠绕过权限提高供给率。
- **充分供给后正确完成率**对应⑤：检查模型是否理解时间、否定和适用条件，以及执行环节是否正确。

定位杠杆时，先统计每个任务在哪一环节首次失败，再估计可挽回任务数与修复成本。某个条件比例低，不等于它造成的总损失最大；到达该环节的任务数也必须纳入判断。

> [!faq]- A004：为什么不能用三个独立测得的平均通过率相乘预测记忆效果？
> 链路分解要求相同任务集上的嵌套条件比例。供给率须在有效保存的任务中计算，正确完成率须在充分供给的任务中计算；若分别换用不同题集，分母与难度就不一致。即使使用正确分母，修改一个环节也可能改变后续比例，需要重新测量整体效果。

## 关键机制

### 写入：保留依据，控制信息损失

**摘要**压缩已有内容；**反思**根据经历归纳规律。二者都可能产生遗漏或错误推断。本文建议将直接证据与推断分开保存：摘要保留关键条件和原始记录位置，反思保留支撑结果与尚未验证的部分。重复写入同一猜测不会增加其证据强度。

**巩固**是把分散记录整理成可复用知识的过程。Anthropic 将利用会话间时间回查记录、修正笔记和重组知识的做法称为 dreaming。它依赖可核查的来源，不能仅靠对旧摘要继续改写就证明新结论正确。[Anthropic，Dreaming can correct memory 与 Dreaming can build new memory representations](https://www.anthropic.com/research/components-of-agent-memory)

写入可以发生在响应前，也可以在后台完成。前者使新信息较快可用，但增加等待时间；后者可集中整理，却可能让下一次读取暂时看不到更新。[LangChain，Writing memories](https://docs.langchain.com/oss/python/concepts/memory#writing-memories)

本文建议：影响紧接着的决策或恢复执行的信息，应及时可靠保存；可以容忍延迟的整理任务再放到后台。后台任务仍需要处理失败重试和重复写入，不能把“已排队”当作“已保存”。

> [!faq]- A005：反思生成的结论为什么不能直接成为已确认事实？
> 反思增加了从经历到规律的推断环节，可能把偶然关系或错误归因写成规则。应保留其证据、条件和未验证状态，再用后续结果核验；模型重复表述或语气肯定都不是确认依据。

### 读取：相关性之外，还要检查有效性

**语义检索**按含义接近程度寻找内容；它不直接判断内容是否真实、最新或属于正确对象。本文建议先按对象和权限限制范围，再综合任务相关性、时间与来源选择记录。**重排序**是对候选结果进一步评分和调整顺序；它改善选择，却不能恢复从未被保存的证据。

输入组装要保留事实之间的条件关系。单条记录相关，不代表多条记录合起来足以支持结论；去重和压缩也不能删除否定条件或时间边界。证据缺失时，应补查或说明信息不足。

### 更新与遗忘：维护当前有效的信息集合

本文建议将**事件发生时间**与**记录写入时间**分开。后写入的内容可能描述较早状态；发生冲突时，应综合来源、适用时间和明确的更正关系，不能机械地“最后写入者胜出”。无法判定时保留冲突，并暂停把争议内容作为确定事实使用。

**失效**表示记录不再适合当前使用，**删除**表示按要求移除相应内容，二者不同。历史记录可在允许的保留范围内留作审计，但必须从当前有效结果中排除；真正删除则需要检查原始记录、索引、缓存、摘要及其他副本。检索不到不等于已经删除。

**记忆污染**是错误或恶意信息进入持久记录后持续影响后续决策。本文建议把保存的内容当作带来源的数据；其中要求改变权限或执行规则的文字，不应自动升级为可信指令。多主体共享记忆时，还要用版本检查或合并机制防止互相覆盖。

> [!faq]- A006：如何判断一次记忆更正或删除是否真正完成？
> 更正要检查当前读取是否采用有效版本，旧内容及其派生摘要是否仍被误用；删除还要检查规定范围内的原始记录、索引、缓存和副本是否移除。两者都需要读写链路验证，不能只依据单次写入成功或一次搜索无结果。

## 分类

分类时先区分三个维度：作用范围、内容用途与存储形式。它们可以交叉组合。

**按作用范围**：短期记忆服务当前线程或任务，长期记忆允许跨会话复用。**线程**是组织一次持续对话及其状态的单位。这里的“短期”不是“不能落盘”：线程状态可以持久化并在以后恢复。[LangChain，Short-term memory 与 Long-term memory](https://docs.langchain.com/oss/python/concepts/memory)

**按内容用途**：情节记忆保存过去发生的经历；语义记忆保存事实与知识；程序性记忆保存如何行动的规则或能力。CoALA 的程序性记忆还包括模型参数和代码；本文聚焦外部显式记录，主要讨论可维护的规则与流程。[CoALA，§4.1](https://arxiv.org/html/2309.02427v3#S4.SS1)

**按存储形式**，以下是本文的工程比较：

| 形式 | 工作方式 | 适用条件 | 主要局限 |
| --- | --- | --- | --- |
| 原始日志 | 按事件顺序保留过程 | 需要回溯完整依据 | 信息多，定位与读取成本较高 |
| 结构化记录 | 用明确字段与标识保存 | 对象和状态关系稳定 | 字段设计不当会丢失上下文 |
| 文本记忆集合 | 分条保存，按需搜索 | 信息异质且持续增长 | 重复、冲突及搜索维护成本 |
| 关系图 | 显式连接对象与关系 | 任务依赖跨对象关系 | 抽取错误和关系更新会传播 |

**文本嵌入向量**是把文本编码成数值序列的表示，可用于比较语义相似度并构建搜索索引；它不是新的记忆用途类别。文件、数据库和向量索引也可以共同服务同一套记忆。

> [!faq]- A007：为什么短期／长期、情节／语义／程序性不能放在同一层互斥分类？
> 短期与长期描述复用范围，情节、语义和程序性描述保存内容的用途，两者回答不同问题。存储形式又是另一维度。把这些维度混在一起，会误以为某一种内容只能存在于某一种范围或技术中。

## 演进与瓶颈

### 关键演进

以下选择能解释设计变化的研究节点，不表示整个领域按单一路线替代。

- **从记录经历到提炼知识（2023）**：Generative Agents 将记忆流、检索与反思连接起来，检索同时考虑近期性、重要性与相关性。它说明保存经历之后还需要选择和归纳；模拟环境中的行为可信度不等于一般任务的事实准确率。[Generative Agents，§4、§6](https://arxiv.org/html/2304.03442v2#S4)
- **从固定输入到分层管理（2023）**：MemGPT 用不同层次的存储及模型发起的管理操作，在有限上下文与外部存储间搬运信息。外部空间扩大，并不意味着单次模型上下文无限扩大；读取与管理仍有成本。[MemGPT，§2](https://arxiv.org/html/2310.08560v2#S2)
- **从找回信息到检验时间与更新（2024）**：LongMemEval 把长期交互记忆拆为信息提取、跨会话推理、时间推理、知识更新与拒答能力。评测范围因此超出“是否搜到相似文字”。[LongMemEval，§3](https://arxiv.org/html/2410.10813v2#S3)
- **从在线记录到离线巩固（2026）**：Anthropic 的工程研究讨论会话间回查来源、修正笔记与重建表示。它把额外计算用在未来的信息准备上；是否值得仍须计入整理成本并在目标任务中验证。[Anthropic，The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)

> [!faq]- A008：分层记忆为什么没有消除上下文限制？
> 分层存储扩大的是可保留的信息总量。模型每次仍只能处理有限输入，外部内容必须经过读取、选择和组装。信息搬运、检索错误及输入裁剪仍然存在，因此存储扩展不能直接等同于可靠使用能力扩展。

以下按能力模型整理问题与干预条件，属于本文的工程分析。

| 瓶颈 | 根因与改进方向 | 代价与验证条件 |
| --- | --- | --- |
| 漏记或压缩失真 | 写入时无法完全预知未来需求；保留关键条件及可回查来源 | 增加存储与检索成本；验证未来题目所需证据是否仍完整 |
| 记录越多，干扰越大 | 重复、过期和矛盾信息竞争输入预算；整理、失效处理与有条件检索 | 清理可能误删；同时测试保留率与最终正确率 |
| 内容正确却未送达 | 查询或索引不匹配，输入裁剪漏掉条件；分段检查读取与组装 | 增加候选会扩大输入；测充分供给率与延迟 |
| 证据送达却被误用 | 时间关系、否定条件或推断被误解；明确结构并验证使用结果 | 更长说明不保证改善；在同一任务集比较 |
| 错误长期传播 | 推断未经核实就被复用；记录依据并及时撤销派生内容 | 溯源与维护增加成本；检查纠错后是否仍出现旧结论 |
| 共享记忆失控 | 越界访问、并发覆盖或指令混入数据；实施隔离和版本检查 | 协作流程更复杂；测试越界和冲突场景是否被正确处理 |

> [!faq]- A009：增加记忆条目后效果下降，应先排查什么？
> 在固定任务集上先找出新增失败的任务，再检查保存内容、取回候选、最终输入与实际使用。条目增加可能改善保存覆盖，却同时引入过期内容和干扰。只有确定失败环节，才能判断应整理记录、调整检索还是改善使用方式。

## 使用场景

记忆适合任务之间存在可复用的信息依赖，且保存和维护的收益超过成本时使用。以下是按任务条件划分的用途，不代表任何具体产品必然有效。

- **持续执行**：当前进展不能仅靠下一次输入重建，需要可靠保存目标、完成状态和待办事项。
- **长期个性化**：任务确实依赖较稳定的偏好，且能够确认所属对象、更新与撤销条件。
- **经验复用**：反馈可核验、任务条件有重复性，过去的有效方法能够在适用范围内再次使用。
- **跨任务协作**：多个执行主体需要共享已确认的信息，并有明确访问范围与冲突处理机制。

若任务彼此独立、当前输入已经充分，记忆可能没有净收益。变化很快且可低成本直接查询的状态，应优先重新观察；只需中断恢复时，先判断检查点是否已经足够。无需为了具备“长期记忆”而增加一套无法维护的知识库。

> [!faq]- A010：什么情况下不应优先引入长期记忆？
> 没有跨任务信息依赖、当前输入足够、历史很快失效，或重新获取信息比维护历史更可靠时，不应优先引入。只为恢复同一任务时，可以先用检查点。判断标准是目标任务中的净收益，而不是记忆功能是否完整。

## 评估与干预

### 指标与测评

先建立按时间排序的任务序列：系统只能使用当前时刻之前可获得的信息。冻结测试答案，禁止在构建记忆时提前读取；按用户或任务隔离数据，避免测试信息通过共享记忆泄漏。

LongMemEval 提供了面向长期交互的能力维度，但其对话问答分数不能独自证明行动安全、隐私隔离或生产可靠性。[LongMemEval，§3](https://arxiv.org/html/2410.10813v2#S3)

下表是本文根据能力模型制定的测评口径；端到端表示从任务输入一直检查到最终结果。

| 指标 | 分母与计入条件 | 测量及解读 |
| --- | --- | --- |
| 端到端任务成功率 | 全部固定测试任务中，最终结果满足成功标准的比例，不要求走记忆路径 | 比较不同基线的实际收益；与总成本共同判断取舍 |
| 记忆链路成功率 Y | 固定历史依赖任务中，S、R、U 均成立的任务比例 | 逐任务检查证据链；只适用于所定义路径 |
| 有效保存率 | 全部历史依赖任务中，所需证据完整有效保存的比例 | 对照原始记录；发现遗漏、失真和失效问题 |
| 保存后充分供给率 | S 成立的任务中，所需证据充分进入输入的比例 | 检查实际模型输入；取回候选不等于已经送达 |
| 充分供给后正确完成率 | R 成立的任务中，正确使用证据并完成任务的比例 | 核对答案或执行结果；反映使用与执行能力 |
| 更新后误用率 | 需要采用更正信息的任务中，仍采用失效内容的比例 | 用更新前后时间序列测试；不能只检查最新记录存在 |
| 无依据作答率 | 所需信息确实不可获得的任务中，仍给出无依据确定结论的比例 | 检查恰当拒答；同时防止有依据时过度拒答 |
| 隔离与删除失败数 | 预设越界读取或删除测试中未达到要求的次数 | 逐条检查副本与读取路径；平均正确率不能抵消此类失败 |
| 总成本与等待时间 | 同一任务序列的全部读、写、整理、模型调用成本和端到端时延 | 后台计算也计入成本；观察中位数及较慢任务的耗时 |

单条记录召回得多，不一定达到任务所需的证据充分性。条件比例的提高也不必然代表整体收益：必须同时观察总成功任务数、无依据回答、更新失效与资源代价。

> [!faq]- A011：长期记忆评测为什么必须遵循时间顺序？
> 记忆只能来自任务发生前已获得的信息。若提前使用后续对话、更正或测试答案，就会把未来信息泄漏给系统，测到的不是实际记忆能力。应按时间逐步写入和测试，并隔离不同用户与任务的数据。

> [!faq]- A012：充分供给率提高，为什么最终成功率仍可能下降？
> 新的供给策略可能加入更多干扰或冲突，使充分供给后的正确完成率下降。在固定题集上，应比较改版救回的任务和新增失败的任务；新增失败更多时，总成功率就会下降。不能只用一个过程指标证明系统改善。

### 干预与验证

本文建议从最简单、能回答目标问题的对照开始：无跨会话记忆、可行预算内的完整历史、摘要记忆，以及待验证的检索记忆。基线取舍使用不限定完成路径的端到端任务成功率与成本，Y 仅用于诊断记忆链路。它们应使用相同任务、模型和成功标准；输入预算不同的比较要明确标注，并同时报告效果与成本。

1. **定位失败**：记录每个任务首次在哪个环节失去必要条件，优先处理可挽回任务多且代价合理的环节。
2. **单独改变关键机制**：分别改变写入、检索、组装或维护策略，观察它实际影响了哪些任务。移除某个组件以判断其贡献的实验称为**消融实验**。
3. **检查净变化**：在同一测试集比较新增成功和新增失败，同时检查更新、拒答、权限与成本。对有随机性的运行重复测量，避免凭单次差异下结论。
4. **延长验证周期**：让历史持续增长、事实发生更正、记录被撤销，检验收益是否仍保持。清空记忆后的短测试不能证明长期稳定性。

<span style="color: var(--color-red)">记忆优化应以固定任务上的最终收益为准，同时验证信息更新、访问边界和维护成本。</span>

> [!faq]- A013：如何证明一项记忆机制值得保留？
> 用相同任务和判定标准，与简单基线及移除该机制的版本比较，记录新增成功、新增失败与全部成本。再检验历史增长、信息更正和撤销后的效果。只有收益可复现且关键边界未退化，才有依据保留其复杂度。

> [!faq]- A014：设计记忆系统时，应按什么顺序作出关键决定？
> 先明确哪些后续任务需要哪些历史信息，再确定保存范围、依据与有效期；随后设计读取、输入组装、更新和删除方式，最后才选择存储与索引技术。用固定任务的端到端效果验证取舍。若历史依赖不成立或维护成本超过收益，就缩小记忆范围。
